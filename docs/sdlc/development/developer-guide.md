<!-- sdlc:auto:start overview -->
BMI is a simple BMI calculator scaffold generated by the Quorq AI SDLC platform. It is split into two independently-run apps in one repo: a Vite + React 19 SPA (`frontend/`) built from an approved design and currently rendering seeded sample data, and a FastAPI 0.115 service (`backend/`) that has no approved architecture yet beyond a `/health` endpoint and SQLAlchemy/Pydantic scaffolding ready for future routes and models. The backend defaults to a local SQLite file so it runs with no external database, and a `docker-compose.yml` is provided to run Postgres 16 separately when `DATABASE_URL` is pointed at it.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Node.js (for npm, Vite, React 19 tooling)
- npm
- Python 3.12
- pip
- Docker (optional, only if running the Postgres service in docker-compose.yml)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. Clone the repository
2. cd frontend && npm install
3. cd backend && pip install -r requirements.txt
4. (optional) copy .env.example to .env and set values such as DATABASE_URL/ALLOWED_ORIGINS/VITE_API_BASE_URL as needed
5. (optional) docker-compose up db -- only needed if pointing the backend at Postgres instead of the default SQLite file
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Backend routes are organized one router per approved architecture component, with each endpoint stubbed to return a typed StubResponse until implemented (see schemas.py)
- SQLAlchemy models all inherit from the shared Base in database.py; main.py imports models before calling Base.metadata.create_all
- Backend configuration is environment-variable driven with safe local defaults: DATABASE_URL defaults to sqlite:///./app.db, ALLOWED_ORIGINS defaults to the Vite dev server origins
- Frontend API access is centralized in src/lib/api.ts (apiFetch helper), configured via VITE_API_BASE_URL and VITE_API_SECRET_KEY (sent as a Bearer token)
- Frontend screens currently render seeded/sample data rather than calling the API; api.ts is the intended integration seam
- Code style enforced via ruff (backend) and ESLint + Prettier (frontend); Vitest component tests live beside the components they cover, Playwright specs live in e2e/
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| Frontend calls to the API fail with a CORS error | Set ALLOWED_ORIGINS on the backend (comma-separated) to include the frontend's origin, or run both on the documented dev defaults (http://localhost:5173 / http://127.0.0.1:5173) |
| `pytest` run from backend/ fails to import app | Run pytest from the backend/ directory so pytest.ini's pythonpath = . applies, or set PYTHONPATH to the backend directory |
| `npm run test:e2e` fails to start the backend webServer | Playwright's local run expects a virtualenv at backend/.venv with dependencies installed; create it (python -m venv .venv && .venv/bin/pip install -r requirements.txt) before running e2e tests without E2E_BASE_URL |
| Backend data is lost between runs or you need a real database | Set DATABASE_URL to a Postgres connection string (e.g. matching docker-compose.yml's app/app/app on localhost:5432) instead of the default SQLite file |
| `npm run build` succeeds but deployment fails on type errors | Run `npm run typecheck` (tsc --noEmit) before shipping, since build does not typecheck |
